# 任务栈水位测试

`stack_test.c/.h` 使用 CMSIS-RTOS2，由被测任务自行调用，不创建线程、信号量或其他 RTOS 对象，不需要修改 CubeMX 生成配置。默认关闭，不增加常规运行时的采样负担。

## 启用与观察

1. 将 `stack_test.h` 中的 `STACK_TEST_ENABLED` 改为 `1U`，或对整个目标添加编译定义 `STACK_TEST_ENABLED=1`，然后重新构建、烧录。
2. 在调试器中观察 `stack_test_results`：槽位 0 为 Judge，1 为 Power，2 为 Chassis。对应任务必须已由 CubeMX 创建并实际运行；模块不会代替用户创建这些任务。
3. `thread_id` 为 `NULL` 表示该槽位尚未采样；`name` 为任务名，`min_free_bytes` 为任务启动以来最小剩余栈字节数，`sample_tick` 为最近采样时间。
4. 三个任务在初始化后和循环中已有采样点。首次立即采样，之后每秒最多采样一次；高水位由内核持续维护，因此两次采样之间发生过的栈峰值不会因采样间隔直接丢失。
5. 完成全速测试后观察结果，再在 CubeMX 中调整对应任务栈并重新生成代码。重新生成后检查 `.stack_size`，该字段的单位为字节；界面若以 32 位字填写，字数乘 4 才是字节数。最后关闭采样开关并复测实际发布配置。

`stack_test_results` 仅用于调试器观察，各任务独立更新自己的槽位，不保证整个数组在同一时刻更新。不要在固件中把它当作任务间同步快照。暂停调试器可能改变通信时序，应在全速运行覆盖异常路径后再观察。

## 接入其他任务

为新任务选择未使用的槽位，例如 3。每个槽位只允许一个任务写入，不得从 ISR 调用。任务退出前的最后一次采样结果会保留；已保存的 `thread_id` 仅用于标识，不应再用于查询已退出任务。

```c
#include "stack_test.h"

/* 放在任务初始化后或现有循环中，不另加延时。 */
#if STACK_TEST_ENABLED
StackTest_Record(3U);
#endif
```

内部通过 `osThreadGetId()` 获取调用任务，再调用 `osThreadGetStackSpace(thread_id)`，等价于 `osThreadGetStackSpace(osThreadGetId())`。不直接使用 FreeRTOS 内核 API，也不调用 `printf` 或格式化输出。

## 根据结果调整栈

观察到的最大使用量约为“配置栈字节数减去 `min_free_bytes`”。这只是已执行路径的测量值，不是所有潜在路径的安全上界；还要结合编译器 `.su` 调用链分析保留余量。检测依赖栈填充标记，未写入的保留空间可能未被完整计入，不能仅凭高水位定最终栈大小。

至少覆盖启动初始化、最大帧、半帧与连续多帧、坏帧重同步、命令队列满、UART 错误重启、收发并行与发送超时，以及电机离线、功率限制和模式切换。采样函数自身也会占用少量栈，测量结果包含该开销。
