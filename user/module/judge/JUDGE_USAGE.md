# 哨兵裁判常规链路收发

协议依据为同目录的《RoboMaster 2027 机甲大师高校系列赛通信协议 V1.0.0（20261029）》。常规链路连接电源管理模块 User 串口，当前为 USART6，115200 bit/s、8N1。

## 硬件配置

已核对当前生成代码：

- USART6_RX：DMA2 Stream1 / Channel5，**Circular**。
- USART6_TX：DMA2 Stream6 / Channel5，**Normal**。
- USART6 全局中断、DMA RX/TX 中断已启用，抢占优先级为 5。
- RX 为 PG9，TX 为 PG14；外设数据和内存数据宽度均为字节，内存地址递增。

保持 RX Circular 与 TX Normal：TX Circular 会循环发送同一帧，发送路径不在运行时检查该生成配置。若以后需要修改模式，应在 CubeMX 的 USART6 → DMA Settings 中配置并重新生成，不直接修改生成区或在运行时覆盖 DMA 模式。

`HAL_UARTEx_ReceiveToIdle_DMA()` 在接收启动时启用 IDLE。接收保留 HT/TC 中断。Normal DMA 的完成还要经过 USART TC 中断，HAL 在其中把 `huart6.gState` 恢复为 `HAL_UART_STATE_READY`；任务以该状态判断上一帧是否结束，不另设完成回调和标志。

`JudgeSem` 和 `judge_task` 由用户在 CubeMX 创建，不在 `Core/Src/freertos.c` 手写定义或创建。对应说明位于 `user/task/judge_task/judge_task.c` 开头：线程名 `judge_task`、入口 `Judge_Task`、Normal 优先级、2048 字节栈；二值信号量名 `JudgeSem`、最大值 1、初值 0，生成句柄为 `JudgeSemHandle`。若栈单位为 32 位字，填 512。

移除旧用户区定义后，必须重新生成该信号量；在用户完成配置前，链接会报告 `JudgeSemHandle` 未定义。代码不提供弱定义或空句柄占位。没有独立发送任务或动态队列分配。

## 帧与 CRC

线上格式为：

```text
SOF(1) | data_length(2) | seq(1) | CRC8(1) | cmd_id(2) | data(n) | CRC16(2)
```

接收时直接从静态拼帧缓冲区逐字节按小端读取长度、命令码和包尾 CRC16，不再创建 `judge_frame_t` 整帧临时副本。CRC 通过后将载荷指针、长度与序号传给分发函数；分发同步完成状态更新和命令入队，不保留载荷指针，返回后才移动拼帧缓冲区。

协议结构体不是可直接发送的固定线性布局：实际载荷长度可变，结构体也可能有内存填充。因此收发均显式编码字节，不能将 `sizeof(judge_frame_t)` 作为发送长度。

CRC8/CRC16 使用协议附录的 256 项查表值，初值分别为 `0xFF`、`0xFFFF`：

- 帧头 CRC8 覆盖前四字节。
- CRC16 覆盖整帧除末尾 CRC16 外的全部字节，包含帧头中的 CRC8。
- 发送按同一算法生成 CRC，CRC16 低字节在前。

保留实际载荷结构体大小和 `valid_mask` 容量的编译检查；移除原来仅检查帧头大小的断言。线上头尾的访问不依赖其 `sizeof` 或结构体内存布局。

## 接收

```text
USART6 Circular DMA + HT/TC/IDLE
    → 1024 字节 DMA 环形缓冲
    → JudgeSem 唤醒 Judge_Task
    → 读取全部新增字节
    → 最多 127 字节线性拼帧缓冲
    → 头部解码 / CRC8 / 长度 / 包尾解码 / CRC16
    → 命令分发
    → 状态快照 + 交互命令 FIFO
```

DMA 缓冲本身已提供接收环形存储，协议层只保留一份拼帧缓冲，不再重复建立字节环。坏头或坏 CRC 时逐字节滑动重同步，支持一次处理多帧和跨次半帧；完整合法的未知命令按整帧跳过。

HAL 回调在 `../../control/uart` 中只维护环绕、完成或错误标志并释放信号量，不解析协议，也不把回调 `Size` 当作数据长度。USART3 遥控器与 USART6 裁判拥有独立状态。

等待信号量为 10 ms，无新数据的残帧超时为 50 ms，有效命令链路超时为 200 ms。等待超时仍检查 DMA 写位置。DMA 覆盖、UART 错误和链路超时会清空快照、解析状态与尚未发送的请求；UART 启动失败由任务延时后重试。

支持的接收命令：

| 命令 | 内容 |
| --- | --- |
| `0x0001` / `0x0002` / `0x0003` | 比赛状态、结果、机器人血量 |
| `0x0101` / `0x0104` / `0x0105` | 场地事件、裁判警告、飞镖信息 |
| `0x0201` / `0x0202` / `0x0203` / `0x0204` | 机器人性能、缓冲与热量、位置、增益 |
| `0x0206` / `0x0207` / `0x0208` / `0x0209` | 伤害、射击、发弹量、RFID |
| `0x020B` / `0x020D` | 地面机器人位置、哨兵决策同步 |
| `0x0301` / `0x0303` | 机器人交互、小地图指令 |

状态量继续保存在 `judge_data` 总包中，USB 和其他任务可直接读取。`0x0301` 和 `0x0303` 另外进入深度 4 的命令 FIFO，业务任务通过 `judge_read_command()` 顺序取出，按实际 `data_length` 和时间戳处理。队列满时丢新，返回一次 `JUDGE_COMMAND_LOST`；接收流重置也返回该状态，包括首次初始化。调用方收到 LOST 后应回退业务状态，不能默认命令连续无缺失。总包中的最新交互内容不替代命令队列。

## 发送接口

当前按现有预留类型接入 `0x0301`：

- `judge_send_sentry(const sentry_cmd_t *)`：封装子内容 `0x0120`，4 字节指令，接收者为裁判服务器 `0x8080`。
- `judge_send_interaction(data_cmd_id, receiver_id, data, length)`：发送任意 `0x0301` 子内容，载荷最多 112 字节，超长请求被丢弃。

两个接口都没有返回值。发送者 ID 在组帧时从 200 ms 内有效的机器人性能数据取得，不使用虚构 ID；裁判离线时请求被丢弃。子内容 ID、接收者 ID、阵营和载荷长度的合法性由调用者保证，模块不再检查。其他 UI 子内容、路径 `0x0307`、自定义消息 `0x0308` 与图传链路不在本轮发送范围内。

当前唯一调用者是 USB 任务：`usb_receive_process()` 收到上位机哨兵指令帧（帧头 `0x1003`，16 字节，载荷为 `sentry_cmd_t`）后调用 `judge_send_sentry()`，本机不解释指令各位。

业务任务显式调用发送接口，模块不会自动发复活、兑换、姿态切换等动作。指令各位含义、单调请求次数与业务重试决策由调用者维护。

发送流程为：

```text
业务显式请求
    → 单条待发请求，新请求覆盖尚未发出的旧请求
    → JudgeSem 唤醒同一 Judge_Task
    → 串口空闲且距上一帧不少于 34 ms
    → judge_pack_tx()：取走请求、确认机器人状态在线、整帧编码、seq、CRC8/CRC16
    → Normal DMA 发送
```

只保留最新一条请求，适合周期性重发的状态型指令；需要连发多条不同指令时，调用者应间隔不少于一个发送间隔。序号每组一帧递增，按 8 位回绕。发送数据存放于任务静态缓冲，串口回到就绪状态前不重新组帧。

保留的故障处理只有三项：

- 串口忙：`huart6.gState` 未就绪时不组帧、不启动，待发请求保留到下次唤醒。
- 发送卡死：启动后超过 50 ms 仍未就绪时调用 `HAL_UART_AbortTransmit()`，中止后才允许下一帧；被中止的帧不重发，因为远端可能已经收到。
- 启动失败：`HAL_UART_Transmit_DMA()` 未返回 `HAL_OK` 时本条请求丢弃，由调用者下一次请求补发。

USART6 的帧错误、噪声和溢出仍由接收路径的 `error_pending` 触发重启接收，并清空尚未发出的请求。没有发送状态查询接口；是否执行复活、兑换、姿态切换，应从真实下行状态如 `0x020D` 确认。

没有其他任务直接发送 USART6，`Judge_Task` 是唯一发送消费者。

## 频率与带宽

所有已接入的 `0x0301` 子内容合用 **30 Hz** 上限，由 `ceil(1000 / 30) = 34 ms` 的最小起发间隔保证，不再维护滚动一秒的帧数和字节数窗口，也没有本机字节预算接口。

协议规定每个接收方每 1000 ms 的基准接收上限为：普通相关机器人 3720 字节，哨兵/雷达 5120 字节，再乘己方基地已损血量对应系数 `λ = 1 - Δ / 20000`，且该额度可能被其他己方机器人同时使用。本机按 30 Hz 发送最长 127 字节帧时约 3810 B/s，可能超过普通机器人的接收额度；发送长载荷机器人交互时由调用者自行降低请求频率。4 字节哨兵指令整帧 19 字节，不受此影响。

## 快照同步与断点调试

裁判数据统一保存在公开的 `judge_data` 总包中，Judge_Task 在调度锁内更新字段和有效时间；其他任务可直接读取，不能从 ISR 访问。中断继续只记录 DMA 环绕和完成事件，不解析协议。

原子函数本身不是断点与全速运行不同的根因。断点暂停时，DMA/串口可能继续工作，RTOS tick 可能停止或延迟处理，DMA 还可能多次环绕但只保留一个中断挂起位。长时间停在回调、读取 DMA 或调度锁内都可能改变结果。应在接口完成后设置断点，并用全速运行观察真实收发、超时和任务时序；不能承诺断点暂停后仍不丢数据。

`judge_data_is_fresh()` 使用 200 ms 窗口，适用于功率任务消费的两个 10 Hz 命令；1 Hz 状态和触发事件按业务周期读取有效位及时间戳。USB 转发不使用该窗口：`usb_send_update()` 按各命令的有效位和 `update_tick` 判断是否有新帧，有新帧转发一次，没有新帧或链路清空时不发送、不补发清零包。2027 `0x0202` 没有实测底盘功率，底盘适配不将其保留字段作为功率测量。
