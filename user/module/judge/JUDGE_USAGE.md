# 哨兵裁判常规链路收发

协议依据为同目录的《RoboMaster 2027 机甲大师高校系列赛通信协议 V1.0.0（20261029）》。常规链路连接电源管理模块 User 串口，当前为 USART6，115200 bit/s、8N1。

## 硬件配置

已核对当前生成代码：

- USART6_RX：DMA2 Stream1 / Channel5，**Circular**。
- USART6_TX：DMA2 Stream6 / Channel5，**Normal**。
- USART6 全局中断、DMA RX/TX 中断已启用，抢占优先级为 5。
- RX 为 PG9，TX 为 PG14；外设数据和内存数据宽度均为字节，内存地址递增。

保持 RX Circular 与 TX Normal：TX Circular 会循环发送同一帧，代码会返回 `JUDGE_TX_CONFIG_ERROR` 并拒绝启动。若以后需要修改模式，应在 CubeMX 的 USART6 → DMA Settings 中配置并重新生成，不直接修改生成区或在运行时覆盖 DMA 模式。

`HAL_UARTEx_ReceiveToIdle_DMA()` 在接收启动时启用 IDLE。接收保留 HT/TC 中断，发送不需要 HT 中断。Normal DMA 的完成还要经过 USART TC 中断，`HAL_UART_TxCpltCallback()` 表示最后一个字节已发送完成，不能仅以 DMA 搬运完成判定串口帧结束。

本轮没有修改生成文件。既有 `JudgeSem` 和 `judge_task` 保留在 `Core/Src/freertos.c` 用户保留区；二值信号量最大值 1、初值 0，任务 Normal 优先级、2048 字节栈。没有新增线程、独立发送任务或动态队列分配。

## 帧与 CRC

线上格式为：

```text
SOF(1) | data_length(2) | seq(1) | CRC8(1) | cmd_id(2) | data(n) | CRC16(2)
```

`judge_frame_t` 是解码后的整帧对象，包含 `frame_header_t header`、命令码、数据数组和 `frame_tail_t tail`。头部长度、命令码和包尾 CRC16 都逐字节按小端解码；包尾读取到 `frame.tail.crc16` 后参与比较。

该对象不是可直接发送的固定线性布局：实际载荷长度可变，结构体也可能有内存填充。因此收发均显式编码字节，不能将 `sizeof(judge_frame_t)` 作为发送长度。

CRC8/CRC16 使用协议附录的 256 项查表值，初值分别为 `0xFF`、`0xFFFF`：

- 帧头 CRC8 覆盖前四字节。
- CRC16 覆盖整帧除末尾 CRC16 外的全部字节，包含帧头中的 CRC8。
- 发送按同一算法生成 CRC，CRC16 低字节在前。

保留实际载荷结构体大小和 `valid_mask` 容量的编译检查；移除原来仅检查帧头大小的断言。线上头尾的访问不依赖其 `sizeof` 或结构体内存布局。

## 接收

```text
USART6 Circular DMA + HT/TC/IDLE
    → 1024 字节 DMA 环形缓冲
    → JudgeSem 唤醒 Judge_Task
    → 读取全部新增字节
    → 最多 127 字节线性拼帧缓冲
    → 头部解码 / CRC8 / 长度 / 包尾解码 / CRC16
    → 命令分发
    → 状态快照 + 交互命令 FIFO
```

DMA 缓冲本身已提供接收环形存储，协议层只保留一份拼帧缓冲，不再重复建立字节环。坏头或坏 CRC 时逐字节滑动重同步，支持一次处理多帧和跨次半帧；完整合法的未知命令按整帧跳过。

HAL 回调在 `user/peripheral/uart/user_uart.c` 中只维护环绕、完成或错误标志并释放信号量，不解析协议，也不把回调 `Size` 当作数据长度。USART3 遥控器与 USART6 裁判拥有独立状态。

等待信号量为 10 ms，无新数据的残帧超时为 50 ms，有效命令链路超时为 200 ms。等待超时仍检查 DMA 写位置。DMA 覆盖、UART 错误和链路超时会清空快照、解析状态与尚未发送的队列请求；UART 启动失败由任务延时后重试。

支持的接收命令：

| 命令 | 内容 |
| --- | --- |
| `0x0001` / `0x0002` / `0x0003` | 比赛状态、结果、机器人血量 |
| `0x0101` / `0x0104` / `0x0105` | 场地事件、裁判警告、飞镖信息 |
| `0x0201` / `0x0202` / `0x0203` / `0x0204` | 机器人性能、缓冲与热量、位置、增益 |
| `0x0206` / `0x0207` / `0x0208` / `0x0209` | 伤害、射击、发弹量、RFID |
| `0x020B` / `0x020D` | 地面机器人位置、哨兵决策同步 |
| `0x0301` / `0x0303` | 机器人交互、小地图指令 |

状态量继续保存在双缓冲快照。`0x0301` 和 `0x0303` 另外进入深度 4 的命令 FIFO，业务任务通过 `judge_read_command()` 顺序取出，按实际 `data_length` 和时间戳处理。队列满时丢新，返回一次 `JUDGE_COMMAND_LOST`；接收流重置也返回该状态，包括首次初始化。调用方收到 LOST 后应回退业务状态，不能默认命令连续无缺失。快照中的最新交互内容不替代命令队列。

## 发送接口

当前按现有预留类型接入 `0x0301`：

- `judge_send_sentry(const sentry_cmd_t *)`：封装子内容 `0x0120`，4 字节指令，接收者为裁判服务器 `0x8080`。
- `judge_send_interaction(data_cmd_id, receiver_id, data, length)`：支持 `0x0200～0x02FF` 己方机器人交互；也支持前述 `0x0120`。

发送者 ID 自动从 200 ms 内有效的机器人性能数据取得，必须是哨兵 7 或 107；不使用虚构 ID。机器人交互检查己方阵营、合法机器人 ID 和最大 112 字节内容。其他 UI 子内容、路径 `0x0307`、自定义消息 `0x0308` 与图传链路不在本轮发送范围内。

业务任务显式调用发送接口，模块不会自动发复活、兑换、姿态切换等动作。指令各位含义、单调请求次数与业务重试决策由调用者维护。

发送流程为：

```text
业务显式请求
    → 深度 4 发送 FIFO，满则拒绝新请求
    → JudgeSem 唤醒同一 Judge_Task
    → 复核发送者在线状态与 500 ms 请求有效期
    → 整帧编码、小端序、seq、CRC8/CRC16
    → 频率与整帧字节预算检查
    → Normal DMA 发送
    → USART TC 完成，或错误/超时中止
```

`JUDGE_TX_QUEUED` 只代表本机接受请求，不表示已发送或远端已执行。序号在 DMA 成功启动后递增，按 8 位回绕；启动失败不消耗序号。发送数据存放于任务静态缓冲，DMA 完成或成功中止前不复用。

入队接口即时返回参数无效、队列满、离线、未就绪或配置错误。`judge_read_tx_status()` 返回最近处理请求的传输状态、子内容 ID、接收者和序号，区分请求过期、UART 忙、DMA 错误和超时；它不是逐条请求完成日志。链路重置会清空队列，不为每条积压请求生成独立完成通知。

- DMA 尚未成功启动：BUSY 或启动失败可在请求有效期内重试。
- DMA 已成功启动：发生错误或超过 50 ms 未完成时中止，不自动重发，因为远端可能已经收到完整指令。
- 中止失败：保持原故障和缓冲区，后续唤醒继续中止，不能覆盖尚可能被 DMA 使用的数据。
- `JUDGE_TX_DONE` 仅表示本机 UART 完成。是否执行复活、兑换、姿态切换，应从真实下行状态如 `0x020D` 确认。

没有其他任务直接发送 USART6，`Judge_Task` 是唯一发送消费者。

## 频率与带宽

所有已接入的 `0x0301` 子内容合用 **30 Hz** 上限，不为不同子内容分别开额度。使用至少 `ceil(tick_frequency / 30)` 的起发间隔，并维护滚动一秒的帧数、整帧字节数；窗口边界不会集中补发。

本机整帧字节预算默认 **3000 B/s**，由 `judge_set_tx_bandwidth(bytes_per_second)` 调整，设为 0 暂停新帧。任务还取该预算与实际 8N1 波特率对应字节率的较小值。帧头、命令码、交互头和 CRC 均计入本机预算；失败或中止的已启动帧仍按完整长度扣除，以免低估实际占用。

**3000 B/s 是本机自限值，不是接收方可用额度的保证。** 协议规定每个接收方每 1000 ms 的基准接收上限为：普通相关机器人 3720 字节，哨兵/雷达 5120 字节，再乘己方基地已损血量对应系数 `λ = 1 - Δ / 20000`。该额度还可能被其他己方机器人同时使用。

队伍需要根据真实基地损血、目标接收方和其他发送者的占用，为本机分配预算并调用设置接口。当前不根据一份当前基地血量猜测最大血量或剩余额度，也不声称已自动协调全队带宽。

## 快照同步与断点调试

快照仍保留双缓冲，发布者只有 Judge_Task，读者只允许任务上下文。写入备用缓冲、发布活动索引和读取复制都使用 CMSIS-OS2 短调度锁；CRC 计算不在锁内。活动索引改为普通标量，不再混用 `__atomic_*` 和 C11 原子类型。

当前单核、任务间访问模式不需要额外的原子内建操作。调度锁保护完整复制并通过 RTOS 的编译器/内存屏障保证临界区顺序；中断继续记录 DMA 环绕和完成事件，不能从 ISR 调用快照或命令读取接口。

原子函数本身不是断点与全速运行不同的根因。断点暂停时，DMA/串口可能继续工作，RTOS tick 可能停止或延迟处理，DMA 还可能多次环绕但只保留一个中断挂起位。长时间停在回调、读取 DMA 或调度锁内都可能改变结果。应在接口完成后设置断点，并用全速运行观察真实收发、超时和任务时序；不能承诺断点暂停后仍不丢数据。

`judge_data_is_fresh()` 使用 200 ms 窗口，适用于功率任务消费的两个 10 Hz 命令；1 Hz 状态和触发事件按业务周期读取有效位及时间戳。2027 `0x0202` 没有实测底盘功率，底盘适配不将其保留字段作为功率测量。
